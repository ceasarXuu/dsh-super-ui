# Super UI — 一行字号，两个选项

DeepSeek Harness（DSH）第三方插件。第一个功能把官方的 **设置 → 通用 → 字号大小** 行改造成一行两项：

- **聊天字号**：官方原有的会话内容字号（10–22 px），行为不变；
- **界面字号**：新增的独立缩放（80–150%），作用于聊天以外的一切——左右侧边栏、会话顶栏、设置页、插件页、菜单、对话框与提示条。

这一行同时保留官方的 **更多字体设置** 展开区：正文字体、代码字体、终端字体与代码/终端字号都还在，仍由官方主题服务写入。

| | |
|---|---|
| 包名 | `@ceasarxuu/dsh-super-ui` |
| 宿主要求 | DSH `>=0.2.1-rc.0 <0.3.0`（已在 Desktop 0.2.2-rc.3 实测） |
| 界面位置 | **设置 → 通用** 的字体行（替换官方原行）：聊天字号 + 界面字号 |
| 其他入口 | `插件 → Super UI → 配置`，或 profile patch 中的 `fontScale`（80–150） |
| 依赖 | 宿主端 `@deepseek-ai/schemastery`（配置 schema）；浏览器端只用平台提供的 `react` |
| 许可证 | [MIT](LICENSE) |

## 为什么需要它

官方「字号大小」明确定义为**仅影响会话内容**：它驱动 `--dsh-content-font-size` 与聊天排版阶梯；侧边栏与设置页的字号写在各自组件 CSS 的字面量里，把聊天字号调大并不会带动外壳，而 DSH 没有界面级字号。这个插件在**同一行**里补上缺失的第二根轴，避免出现两个描述相近、让人分不清的字号设置：

- 官方聊天字号控件保留（同一字段、同一主题服务、同样的 `Cmd/Ctrl +/-` 快捷键），改名为 **聊天字号**；
- 旁边新增 **界面字号**，缩放会话列以外的所有字面量界面字号；
- 会话列被重置回出厂字号，聊天正文、工具卡片、输入框只受自己的字号设置影响；
- 官方「更多字体设置」展开区完整保留；
- 界面字号偏好经 Host settings 文档按 profile 持久化，也可通过 profile patch 与官方插件配置界面编辑。

## 使用

1. 安装本 bundle（**插件 → 添加插件**选择本地目录，或在 profile 的 `cordis.patch.yml` 中登记）。
2. 打开 **设置 → 通用**，原来的「字号大小」行变成：
   - **聊天字号**：会话内容字号的 px 步进器，右侧是 **更多字体设置** 展开按钮；
   - **界面字号**：80–150% 步进器（每次 5%，100% 为出厂尺寸），旁边有 **重置**。
3. 界面字号立即生效并跨重启保留。`插件 → Super UI → 配置` 里是同一个 `fontScale` 字段，也可以直接写 profile 覆盖：

```yaml
- id: super-ui
  name: '@ceasarxuu/dsh-super-ui'
  config:
    fontScale: 120   # 界面文字放大 20%，聊天不受影响
```

卸载或停用插件会恢复官方字体行与出厂界面字号；缩放本身无需刷新页面，且不会修改 profile 里的其他内容。

## 作用范围

| 由字体行控制 | 只受聊天字号影响 |
|---|---|
| 界面字号：左侧边栏（会话树、搜索、底部入口）、右侧边栏外壳、会话顶栏、设置/插件页、菜单、对话框、提示条、Tooltip | 会话消息、Markdown、代码块、工具卡片、轨迹视图 |
| 聊天字号：会话内容（官方原有轴，行为不变） | 输入框、附件、审批/提问接管界面 |
| 更多字体设置：正文/代码/终端字体、代码/终端字号 | 侧边栏终端单元格字号（仍由官方终端字号设置控制） |

会话内弹出、但挂载到页面 body 的界面（例如从消息里打开的对话框）会跟随界面字号而不是聊天重置——这属于外壳而不是内容，是有意为之。

## 实现原理

1. **替换原生行**：官方主题插件把字体行注册到 `settings.general.item` 列表槽，cell id 为 `font-size`；列表槽每个 id cell 只渲染一个存活条目，按 `priority`（再按 `order`）取最小者。本插件用同一个 id 且 `priority: -1` 注册，于是**遮蔽**官方行而不是多出一行；若某个槽实现不接受 priority 选项，则回退为独立行 id（降级但仍可用）。
2. **字体走服务**：聊天/代码/终端字号与字体列表从 `ctx.theme.getTheme()` 读取，通过 `ctx.theme.setFontSize()` / `setFontFamily()` 写入；校验、归一化与官方快捷键都由主题服务负责，行则跟随 `theme/change` 更新。
3. **界面缩放走 CSSOM**：一次性遍历所有同源样式表，把字面量 `font-size: <length>` 改写为 `font-size: calc(<length> * var(--dsh-super-ui-scale, 1))`；同一规则里的 `line-height` 只在该规则也缩放了字号时跟随，保证文字行高按比例变化而固定高度/垂直居中的几何不变。直接原地修改活动 CSSOM，选择器优先级、`!important`、`@media` 嵌套与规则顺序与出厂样式表完全一致。
4. 缩放值只是 `<html>` 上一个可继承的自定义属性；会话所在的网格列携带 `--dsh-super-ui-scale: 1`，使其子树内所有 calc() 回到出厂值。
5. MutationObserver 处理启动后才到达的样式表（懒加载客户端模块、插件 HMR）；卸载时逐条恢复被改写的声明。

## 已知限制

- 只改写字面量 `px`/`rem` 字号；`em`、`%` 与关键字仍按继承自然缩放。组件写入的行内 `font-size` 与跨域样式表不处理。
- 不缩放布局几何（图标、内边距、控件高度、侧边栏宽度）——这是字号设置而不是缩放；范围上沿个别固定高度控件可能略显拥挤，80–150% 的区间是刻意保守的。
- `font` 简写只在浏览器接受其中 `calc()` 时缩放（当前 Chromium 支持），否则保持原样。
- 聊天区重置依赖外壳框架结构（右栏列之前的中间网格列）。若未来 DSH 改动框架结构，标记会退化为"全部缩放"：出现视觉退化，但不会抛错。
- 行遮蔽依赖官方字体行继续使用 cell id `font-size`。若未来版本改名，本插件的合并行会消失、官方行回归；界面缩放仍可通过回退注册继续工作。

## 开发

```sh
npm install                     # 仅开发期：jsdom、React、puppeteer-core
npm run build                   # 从 src/client/*.js 重新生成 client.js
npm run verify                  # 构建 + 语法检查 + node --test（21 项）
npm run verify:browser          # 无头 Chromium：计算字号、聊天重置、后插入样式表、卸载恢复（29 项）
npm run verify:row              # 无头 Chromium：合并行几何、展开区、步进不抖动（116 项）
```

`client.js` 是生成产物：DSH 的客户端 loader 不给插件工厂任何模块导入能力，因此可读源码放在 `src/client/` 的片段里（常量、helpers、缩放引擎、字体模型、行组件、插件主体），由 `dev/build-client.mjs` 按文件名顺序拼进 module-loader 外壳。改 `src/client/*.js`，不要手改 `client.js`。

单元测试覆盖 jsdom 中的 CSSOM 改写、注册/遮蔽决策、通过主题服务的字体写入与卸载恢复；两个浏览器探针都通过 `puppeteer-core` 驱动真实 Chromium（`CHROME=/path/to/chrome` 可覆盖默认查找路径）：引擎探针覆盖 jsdom 无法计算的部分，行探针用真实 React 渲染真实组件，箭头遮数值、行溢出或展开区丢失官方字体设置都会直接失败。
